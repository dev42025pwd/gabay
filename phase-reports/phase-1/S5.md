## 1. What was built

**`npm run verify`** (`tools/verify.js`): fifteen checks, cheapest first, one line each, ending `ALL GREEN` or the list of failures; the exit code is the number of failed checks.

| # | Check | What it runs |
|---|---|---|
| 1 | node-version | Node major is 22, else stop (the rest would lie) |
| 2 | node-check | `node --check` on every script in `functions/`, `db/tools/`, `db/seeds/seed.js`, `tools/` |
| 3 | structural-linters | `tools/lint/run.js` on the whole repo; also requires the `ok repo-layout` line |
| 4 | linter-tests | `tools/lint/test` (fails on 0 tests) |
| 5 | tools-tests | `tools/test` (fails on 0 tests) |
| 6–7 | eslint, prettier | `functions/`, `db/tools/`, `tools/`, `.claude/hooks/` with the functions package's pinned tools |
| 8–9 | api-tests, db-tools-tests | (fail on 0 tests) |
| 10–11 | schema-run-1, schema-run-2 | `db/schema.sql` twice on the local PostgreSQL |
| 12 | seed | the test seed with the Auth emulator |
| 13 | functions-health | the Functions emulator; `GET …/api/health` must answer `{status:"ok", db:"ok"}` with an `X-Request-Id` (L126) |
| 14–15 | flutter-analyze, flutter-test | in `app/` |

After every run, green or red, it writes `.verify/last-run.json` (gitignored): a fingerprint of the code, the result, the failed checks, the number of checks that ran. The fingerprint (`tools/fingerprint.js`) hashes the tracked and untracked code files (`app/`, `functions/`, `db/`, `tools/`, `.githooks/`, `.claude/hooks/`, root `package.json`, `firebase.json`, `.claude/settings.json`, `.gitignore`; Markdown excluded). It is taken at the start and the end; code changed during a run fails it. `--only` runs are partial and never count. Verify stops only the processes and ports it started itself.

**Git hooks** (`.githooks/`, enabled with `git config core.hooksPath .githooks`):
- `pre-commit`, in this order: the secret guard (pure shell: any staged `.env*` except the templates); the changelog duplicate guard (a repeated entry number or bullets function per surface); the structural linters on the **staged** content (the index exported to a temp folder) plus `migrations-immutable --staged`; then the version stamp (L129: the patch of each surface the commit touches; a new top entry is a release; a hand-raised valid version above HEAD's is kept; never lowered; the date in Asia/Manila from the commit time). The stamp never blocks.
- `post-commit`: after a `git commit -- <paths>` (a temporary index), re-applies the stamp to the real index so it does not show a staged change reversing it; deliberate staging survives.
- `pre-push`: refuses when a pushed ref, peeled to its commit, is not the checked-out commit; when code files are uncommitted or untracked; when verify fails. Deletions pass.
- `node.sh`: hooks find Node 22 (or fnm) whatever Node the shell has; the secret guard runs even without Node.

**Claude Code hooks** (`.claude/settings.json`, `.claude/hooks/`):
- `Stop` (main session only, L129): blocks until verify has run on the current code; a red run lets the session stop with "verify FAILED on the current code: N of 15 checks ran; failed: …"; fails closed.
- `Stop` (main session only, L130): blocks when screens changed since the session began with no changelog entry, unless the final message has a line "Changelog waived: <reason>"; fails closed.
- `SessionStart`: records HEAD per session, the baseline for the screens hook.
- `PostToolUse` on `Edit|Write|MultiEdit`: the schema-to-form drift linter after any Dart edit; exit 2 feeds violations back.

Hook facts checked against code.claude.com/docs/en/hooks.md this session: the Stop input carries `last_assistant_message` and `stop_hook_active`; a Stop hook blocks with `{"decision":"block","reason":…}` or exit 2; `SubagentStop` is a separate event.

Also: README "Checking your work" and hooks table; root scripts `verify`, `tools:test`; `.gitignore` `.verify/`; `app/pubspec.yaml` `1.0.0+1` → `0.1.0+1`, never stamped (L129); `db/tools/lib/migrations.js` `{ cause: err }` (the one ESLint finding; behaviour unchanged).

## 2. Rulings and design choices

- **L129** (owner): patch bump per touched surface; the verify Stop hook requires a run on the current code and shows a failure; main session only.
- **L130** (owner, after review finding I6): the screens Stop hook blocks until an entry exists or a stated waiver; main session only.
- DESIGN CHOICES (each with its alternative in the coder's reports, accepted by dod-reviewer): guards before the stamp, so a refused commit leaves nothing stamped (the plan lists the stamp first); `session-baseline.js` so work committed mid-session still counts; linting the exported whole index so cross-file linters see `schema.sql`; post-commit re-applies the stamp rather than resetting; pre-push refuses a dirty tree and a non-checked-out ref instead of verifying in a fresh worktree (dependencies would be rebuilt each push); the waiver ignores fenced lines; fixed test fixtures for the version files; `emulators:exec` with a probe script; `node --check` in batches of eight; the test seams `GABAY_NOW`, `GABAY_VERIFY_EMULATOR_TIMEOUT_MS`, `GABAY_VERIFY_TEST_INTERRUPT_MS`, documented in the code.
- Accepted limits (told to the product owner): `git commit --amend` bumps again; branches touching one surface conflict on the version files; a hand-written `.verify/last-run.json` would satisfy the Stop hook; `.claude/settings.local.json` can override hooks; two sessions in one folder contend for `gabay_dev`, the emulator ports and each other's Stop hook.
