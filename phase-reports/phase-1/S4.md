## 1. What was built

Ten linters in `tools/lint/`, plain Node 22 with no dependencies. Each names the file and line it fails on (`path:line: rule: message`), and each has tests that feed it bad samples and expect the failure. The table, the annotations and the accepted limits are in `tools/lint/README.md`.

| Rule | Catches | Source |
|---|---|---|
| `schema-drops` | a `CREATE TABLE` without its `DROP TABLE IF EXISTS` | §8.2 |
| `schema-forms` | a `FieldSpec` that disagrees with `schema.sql` (kind, nullability, length, scale): the drift linter | §7.2, A.13 |
| `no-bare-textfield` | `TextField`, `TextFormField`, `CupertinoTextField` anywhere in `app/lib` except `app/lib/shared/forms/` | rule 7, L128 |
| `colour-literals` | `Color(0x`, `Color.from*(`, `Colors.*`, `CupertinoColors.*`, `primaryColor`, outside `gabay_tokens.dart` | rule 6 |
| `sql-interpolation` | a `${}` or `+` value inside SQL text in `functions/src` | rule 3 |
| `tenant-predicate` | SQL or a `runPaged` call on a tenant-scoped table that does not bind `TenantId` to a `$n` in its `WHERE` (an `INSERT` in its values) | rule 2 |
| `position-privacy` | an import of `core/positioning` outside the allow-list; position and network code in one file outside `core/analytics` | invariant 4, L128 |
| `foreground-manifest` | background location or BLE in the Android manifest and `Info.plist` | Foreground rule |
| `migrations-immutable` | an edited, deleted or renamed committed migration; a bad or repeated number; a file in a subfolder | rule 4, §8.2 |
| `no-snackbar` | `showSnackBar(` / `ScaffoldMessenger` | §4.6 |

The runner `tools/lint/run.js` runs every linter, a chosen few, or an explicit file list (pre-commit). Its exit code is the violation count (max 255). It never passes silently: `--base` or `--root` without a value exits 2, a whole-repo run fails (`repo-layout`) if `db/schema.sql`, `app/lib` or `functions/src` is missing, `--allow-partial` works only together with `--root`, and every linter prints the number of files it scanned.

Two escape hatches, each a comment directly above the SQL with a non-empty reason: `// sql-identifiers:` and `// tenant-scope:`. The linter cannot judge a reason, so REVIEW.md's security pass reads every new one (L128).

Root scripts: `lint:structural`, `test:schema-forms`, `lint:test`.

Deferred by L128 to Phase 2, with sign-in: the route-guard-order lint and the "no raw error text to users" lint (FEATURE_PIPELINE §5.1 items 3 and 5).

## 5. Re-check (dod-reviewer)

"Acceptable with one fix". Every first-pass sample was caught except the documented limits; no new false positives on the repo; the whole run takes 89 ms.
- **I-1 (Important):** a `runPaged` call whose `from` is a constant, comes in through a `...` spread, or is passed as one options variable got no tenant check.
- **Nits:** `\w*Colors` also flagged `tokens.levelColors`; five evasions missing from the README's accepted limits; `--allow-partial` usable without `--root`; single-quoted manifest values; looped tests not asserting line numbers.
- **Design choice 1** (main session): a `${}` wrapped in single quotes still counts as SQL, so `` `venue '${id}' not found` `` is flagged. A false positive costs a quote change; a false negative is an injection; `functions/src` has no such message today. The violation message now says why. *Alternative:* count the quote only after an SQL operator (`=`, `LIKE`, `IN (`), which loses a bare `'${name}'` fragment.

## 8. Accepted limits (review-pass items)

Listed in `tools/lint/README.md` "Accepted limits"; REVIEW.md's security pass points there. In short: SQL assembled by `join`, `concat`, `util.format` or a helper; lower-case SQL with an unquoted `${}` and no `gabay.` prefix; `TenantId = $1 OR …`; a tenant bound only in a subquery or CTE; a destructured `runPaged` alias; `Color(<int>)` and `HSLColor`; a class extending `TextFormField`; a position handed from a ViewModel to a networking service; a tenant parameter whose value comes from the request (the linter cannot see the value's source).
