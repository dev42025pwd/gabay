## 4. DESIGN CHOICES (api-coder; each with its alternative)

1. **Lint concurrency** grouped by event and pull-request number or commit: pushes to `main` are never cancelled; a newer push to a pull request cancels the older run. *Alternative:* group by ref with cancel off for `main`; passed over because a pending run is replaced by a newer pending one, so a `main` commit could lose its lint.
2. **`tools/ci-migrations.js` as a script**, testable with scratch git repositories, keeping `${{ }}` out of `run:`. *Alternative:* inline shell, untestable.
3. **The first push of `main` warns and runs only the file-name rules; a force push of `main` or a shallow clone fails.** *Alternative:* fall back to `origin/main`; passed over because it would skip the check on exactly the commit that matters.
4. **Build caches with plain `actions/cache`**, restore-only under `workflow_run` (GitHub's rule), filled by a manual build on `main`. *Alternative:* trigger `build` on `push: main`, which under L136 is equivalent, simpler and removes the fork-trigger surface; kept for the plan's "after lint passes" wording. **Suggested for revisiting.**
5. **Timeouts:** e2e cap 5 min, job 50; lint cap 10 min (more than 6× the slowest measured check), job 30. *Alternative:* no lint cap; passed over because a hang would end as a cancelled run with no output.
6. **An unknown Linux listener owner counts as busy** (sentinel `-1`). *Alternative:* a new return shape for `listeners()`, touching every caller.
7. **Lint `push:` only on `main`** (the main session's choice for I-B). *Alternative:* all-branch pushes compared with the same base as the pull request.
8. **Gate steps pinned by text computed from `CHECKS`**, so a change to the checks fails the test until the workflow follows. *Alternative:* a literal string, which would drift.
9. **Gate steps limited to an allow-list of keys.** *Alternative:* forbid only `if:`; other keys (`working-directory`, `env`) can also change what a step does.
10. **The record written by temp file and rename**, with a short bounded retry on Windows. *Alternative:* a lock file; a rename is enough for last-writer-wins, and a lock can go stale.
11. **`readState` still returns null for missing or corrupt**; `readStateDetailed` carries the reason. *Alternative:* throw, which would break the callers and the Stop hook's fail-closed paths.
12. **A tag named `main` is not `main`** (`REF_TYPE` checked). *Alternative:* trust `REF_NAME` alone.

- **A leftover emulator export turned one run red (2026-10-08 12:12):** every check passed, but verify ended `FAIL code-changed-during-run`.
