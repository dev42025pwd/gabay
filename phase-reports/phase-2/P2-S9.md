## 1. What was built

All of it is in `app/lib/shared/` plus one feature file. There is no screen yet: S11 builds the maintenance screens on this.

- **`FieldSpec`** (`shared/forms/field_spec.dart`). It has the exact shape the `schema-forms` linter parses: `table`, `name`, `label`, `kind`, `required`, `maxLength`, `scale`, `readOnly`, plus `format` (which the linter ignores). The kinds are `ColKind.text`, `integer`, `flag` and `fk`; an email is a `text` column with `FieldFormat.email`. The label is a function of `AppLocalizations`, so the wording stays in ARB.
- **The resolver** (`spec_form_field.dart`): one spec in, one widget and its validators out.
  - Text and integer fields own a controller and follow later value changes. The ViewModel must echo `onChanged` back verbatim (stated in the doc).
  - `flag` is a switch, never a Yes/No dropdown.
  - Read-only specs render the value with no input.
- **The validators** (`field_validators.dart`, `shared/utils/validators.dart`). They are derived from the spec, never written by hand: required, maxLength, and the integer and email checks. Each message names the field.
- **The FK picker** (`async_lookup_picker.dart`, L151 (5)). This is the async server-search picker of standard §4.10, never a load-all dropdown.
  - It is a full-screen dialog on `ModuleListScaffold` and `PagedListNotifier`, with debounced search, "Load more", the four states, and errors through `formatApiError`.
  - Its rows come from a `LookupFetcher({search, page})` the ViewModel supplies. Phase 2 has no `/api/lookups` route.
  - The held value is always shown and is never cleared by opening or closing the picker. It is marked "(inactive)" when it is inactive, and fetched inactive rows are marked too.
  - An editable `fk` without a fetcher fails an `assert` naming `lookupFetcher`.
  - A validation error reaches screen readers as the field's hint, with an invalid state.
- **The list machinery.**
  - `ModuleListScaffold` gains a debounced search box (350 ms, above the four states) and a "Load more" footer. Both spinners have screen-reader names.
  - `PagedListNotifier` (`shared/components/paged_list_notifier.dart`) holds the fetch lifecycle with a fetch ticket (standard §4.6). A late answer to an old search is dropped. `loadMore` does nothing while a search is loading.
- **The users specs** (`features/admin/users/models/user_field_specs.dart`): `AppUser.Email`, `DisplayName`, `IsActive` and `UserRole.RoleId`. They are real S11 specs, and the linter checks each against `db/schema.sql`. `UserRole` is one row per role-and-tenant choice, each a single selection (L151 (6)).
- **Wording.** 12 ARB strings, each with a description (`app_en.arb`): two validator messages, six for the picker and spinners, four field labels. Tagalog waits for P0-14.
- **Comments only.** In `tools/lint/no-bare-textfield.js` and `schema-forms.js`, "Phase 3" becomes "S9" where the folder now exists, and the `format:` argument is documented as ignored.

## 4. DESIGN CHOICES (flutter-coder; each with its alternative)

1. **The label is a function of `AppLocalizations`,** so the wording stays in ARB and a spec is a `final`, not a `const`. *Alternative:* an ARB key string resolved at build time, which loses compile-time checking.
2. **`format:` is an argument the linter does not check** (email is a shape of a `text` column, not a column type). *Alternative:* an `email` kind, which the linter would have to map to `VARCHAR`.
3. **The value lives in the ViewModel;** the fields are stateless apart from their controller and the debounce timer (MVVM). *Alternative:* fields that keep their own state, which makes reset and reload harder.
4. **The search box sits above the four states,** so it stays while the list loads or fails. *Alternative:* the search box inside the data state, which disappears on an error.
5. **Paging is "Load more", not infinite scroll** (standard §4.6, "rows + footer"). *Alternative:* scroll-triggered loading; `loadMore` is now safe to call from scrolling.
6. **A read-only flag is a disabled switch.** *Alternative:* the text "Yes" or "No", which reads differently from the editable form.
7. **`PagedListNotifier` is split out of the scaffold.** The picker is its second user. *Alternative:* the fetch lifecycle inside the scaffold widget, which the picker could not reuse.
8. **A malformed integer keeps its text,** reports `null` and shows the validator message. Standard §4.10's wording is "a malformed value clears the field". *Alternative:* clear it, which throws away a half-typed minus sign.
9. **The picker's rows come from a fetch function the ViewModel supplies,** with "active rows only" as the fetch function's contract (L151 (5)). *Alternative:* a picker bound to `/api/lookups/:name`, which does not exist until Phase 3.

## 6. Open, outside S9

- **An optional `fk` cannot be cleared** (there is no "none" choice). `UserRole.TenantId` is NULL for platform roles, so S11 must hide that picker or add a way to clear it.
- **S11 must always pass `currentOption`.** Without it, a deactivated role or venue shows its raw id instead of its label marked "(inactive)".
- **The echo-back contract.** A ViewModel that trims as the user types resets the box and loses focus. S11's ViewModels echo `onChanged` verbatim and trim on save.
- **Memory under "Load more"** keeps every fetched page. For the audit viewer, whose log grows without limit, this is unmeasured; the plan states no target.
