## 1. What was built

- **The token check** (`functions/src/auth/firebaseVerifier.js`). It is the only code that talks to `firebase-admin` 14.5.0 (E-08). It calls `verifyIdToken(token, true)`, so revoked and Firebase-disabled users are refused. A failure it recognises gives 401; anything else gives 503 (fails closed).
- **The identity lookup** (`auth/identityStore.js`). The Firebase UID maps to `AppUser`, otherwise to `ShopperAccount` (Q12). Admin first is a labelled DESIGN CHOICE, ruled later.
- **The access lookup and the permission merge** (`auth/accessStore.js`, `auth/permissionMerge.js`).
  - Role rows are OR-ed, and a `UserPermission` row replaces the merged role row.
  - A platform role counts only on a NULL-tenant row whose role has `IsPlatformRole` set. Any other NULL-tenant row is ignored and logged.
  - SUPERADMIN needs both conditions.
  - The maps have no prototype.
- **The middleware** (`middleware/auth.js`):
  - the Bearer header;
  - the session age, `now − auth_time` against `auth.idTokenMaxAgeS` (default 28,800 s, L151);
  - an inactive `AppUser` is refused;
  - the actor is bound for the request (actorContext);
  - `requireAdminUser`.
- **`GET /api/me`** (`routes/me.js`, mounted by `routes/api.js` behind auth). It returns the user, `isSuperAdmin`, the platform roles, and each tenant (from `UserRole`) with its roles and merged permissions.
- **Config.**
  - `FIREBASE_PROJECT_ID` and `FIREBASE_AUTH_EMULATOR_HOST` are added.
  - The emulator host is refused unless `NODE_ENV` is explicitly `development` or `test` (L151), because emulator mode accepts unsigned tokens.
  - `.env.example` is updated.
- **Docs.**
  - Blueprint invariant 16 gains `auth.idTokenMaxAgeS` (and drops `auth.singleSession`, Q2), and Part 4 gains anchor 4.14 (Blueprint 0.26).
  - `docs/testing/E2E_Test_Cases_Manual.md` gains the six seeded accounts and cases 2.1–2.19.

## 4. DESIGN CHOICES (api-coder; each with its alternative)

1. **The session-age default** is 28,800 s, measured from `auth_time`. Ruled by L151, which replaced the coder's 3,600 s from `iat`.
2. **Status codes.** An inactive, disabled, too-old or invalid token gives 401, which signs the client out (Q5). A Firebase identity with no Gabay account, or a shopper on an admin route, gives 403. *Alternative:* 403 for inactive accounts too, but the client would then not sign them out.
3. **Firebase failures are classified deny-by-default.** A fixed list gives 401; everything else gives 503. *Alternative:* a deny-list, which fails open on an unknown code.
4. **Auth is mounted per route group,** so an anonymous unknown path stays 404. *Alternative:* a global 401 before routing.
5. **`req.user` carries no tenant** (rule 2; invariant 13). A shopper binds no actor.
6. **The `/api/me` shape:** a route with no row is omitted (not granted); an inactive tenant is listed with `isActive:false`; user overrides apply in every tenant (the schema has no tenant on `UserPermission`). *Alternative:* list every route with false flags.
7. **No default emulator host;** it must be set in `.env`.
8. **Admin before shopper** when one UID is both. Labelled for a later ruling (P0-10).
9. **The test double.** The middleware tests inject a double, because verify runs the API tests before the seed starts the emulator. The real SDK is exercised against a fake Identity Toolkit and end to end (I4).

## 6. Open, outside S1

- **The tenant switcher list:** a SUPERADMIN, or a user with only platform roles, gets no tenant list from `/api/me`. S2 and S10 supply it.
- **Overrides** (L151): only SUPERADMIN, or an admin who is MALL_ADMIN in every tenant of the user, may write them. This is enforced in S6 and S7.
- **Revocation costs** one Firebase call per request (unmeasured; no target in plan §8). A short verdict cache is a later option.
- **The deploy runbook** must state `NODE_ENV=production` and that the emulator variable is never set (first deploy, L109).
